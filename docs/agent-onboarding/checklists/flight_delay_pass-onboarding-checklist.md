## Phase 2 — `./addapi.sh flight-delay-pass`

**Status: BLOCKED — by design.**

The `addapi.sh` portal-wizard flow can mint an OAuth1 signing key for this API,
but doing so is insufficient: the live sandbox will return `403` until:

1. The issuer is on-boarded as a Flight Delay Pass tenant by the Mastercard
   implementation team (≤26 days).
2. The project's Client Key is shared with that team and whitelisted.
3. A `clientId` (merchant) and `propositionCode` are configured by Mastercard
   and supplied as request parameters.

Action for the human:
```
Email your Mastercard representative requesting Flight Delay Pass tenant
provisioning for project <portal-project-name>. Share the project's
Consumer Key (X-OpenApi-ClientId), the `clientId`, and `propositionCode`
they assign back, then add them to config/.env as:

  FLIGHT_DELAY_PASS_CONSUMER_KEY=<...>
  FLIGHT_DELAY_PASS_SIGNING_KEY_PATH=config/keys/flight_delay_pass.p12
  FLIGHT_DELAY_PASS_SIGNING_KEY_ALIAS=<alias>
  FLIGHT_DELAY_PASS_SIGNING_KEY_PASSWORD=<password>
  FLIGHT_DELAY_PASS_ENCRYPTION_KEY_PATH=config/keys/flight_delay_pass_enc.pem
  FLIGHT_DELAY_PASS_CLIENT_ID=<merchant clientId>
  FLIGHT_DELAY_PASS_PROPOSITION_CODE=<proposition code>
```
